# 1.1 入出力高速化と基本テンプレート設計

## 1. 入出力高速化のメカニズム

競技プログラミングにおいて、標準的な `std::cin` / `std::cout` はデフォルトのままでは低速であり、データ数 $N \ge 10^5$ の問題では TLE（実行時間制限超過）の原因となる。

### ① `std::ios::sync_with_stdio(false);`
- **原理**: C言語の入出力関数（`scanf` / `printf`）と C++ のストリーム入出力（`cin` / `cout`）の間で保たれている同期バッファを解除する。
- **効果**: C++ 独自のバッファリングが有効になり、入出力が `scanf` / `printf` と同等以上の速度になる。
- **注意点（混ぜるな危険）**: 同期を解除した後は、**`cin` / `cout` と `scanf` / `printf` を絶対に併用しないこと**。出力順序が崩れて WA となる。

### ② `std::cin.tie(nullptr);`
- **原理**: `cin` と `cout` の「タイ（結合）」を解除する。
- **デフォルトの挙動**: 通常は対話型アプリを想定し、`cin` で入力を受け付ける直前に自動的に `cout.flush()`（溜まった出力バッファを画面に強制書き出し）が実行される。
- **効果**: 結合を解くことで、入力直前の無駄なシステムコール（フラッシュ）を抑止し、高速化する。

### ③ `'\n'` vs `std::endl`
- **`std::endl`**: 改行文字 `\n` を出力した上で、**バッファの強制フラッシュ（flush）** を行う。
- **`'\n'`**: バッファに改行文字を書き込むのみ。バッファがいっぱいになるまで OS への書き出しを遅延させるため圧倒的に高速。
- **結論**: $N = 2 \times 10^5$ 行の出力で `std::endl` を使うと、フラッシュ処理の多発により確実に TLE になる。競プロでは必ず `'\n'` を使用する。*(※インタラクティブ問題を除く)*

## 2. 定数設計と `constexpr`

### `const` と `constexpr` の違い
- `const`: 「書き換え不能（Read-Only）」を保証する。実行時に値が決まる変数（例: `const int x = n;`）にも適用可能。
- `constexpr`: 「**コンパイル時に値が完全に確定している定数**」を表す。

### なぜ競プロで `constexpr` を使うのか？
1. **実行時オーバーヘッドがゼロ**: プログラム起動前のコンパイル時点で値が決まるため、実行時の初期化コストが発生しない。
2. **固定長配列のサイズに使える**: C++ の配列サイズ指定（`std::array<int, SIZE>` 等）にはコンパイル時定数が必要。
3. **型安全性**: 古い `#define` マクロと異なり、明示的な型を持つため予期せぬ演算優先順位バグを防げる。

## 3. 実装上の落とし穴・レビューでの学び

### 型アンマッチによる「値の消失バグ」
```cpp
// NG例:
constexpr int INF = 1LL << 60;
```
- 右辺の `1LL << 60` は 64bit 整数（$2^{60} \approx 1.15 \times 10^{18}$）。
- しかし左辺が 32bit の `int` であるため、上位ビットが切り捨てられる。
- $2^{60}$ の下位 32bit はすべて `0` であるため、**`INF` の値が `0` に化けてしまう**。
- **対策**: 左辺の型を正しく `ll` (`long long`) に指定する。
```cpp
// OK例:
constexpr ll INF = 1LL << 60;
```

### 静的解析の警告（Include What You Use）
- `<stack>` や `<queue>` などを include していると、「使われていないヘッダがある」という警告が出る場合がある。
- テンプレートは将来の問題を解くための「道具箱」であるため、事前 include は問題ない（実戦では無視して構わない）。

using namespace std;
using ll = long long;

constexpr ll INF = 1LL << 60;

int main() {
  cin.tie(nullptr);
  ios::sync_with_stdio(false);

  // ここから処理

  return 0;
}
