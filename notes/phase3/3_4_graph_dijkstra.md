# 3.4 グラフ探索と最短経路（ダイクストラ法・BFS/DFS）

## 1. 最短経路アルゴリズムの選定マトリクス

グラフの辺の重みや求めたい対象によって、最適なアルゴリズムを選択する。

| アルゴリズム | 辺の重み条件 | 単一始点 / 全点対 | 計算量 | 使用する主なデータ構造 |
| :--- | :--- | :---: | :---: | :--- |
| **BFS (幅優先探索)** | 重みなし（すべて 1） | 単一始点 | $O(V + E)$ | `std::queue` |
| **0-1 BFS** | 重みが $0$ または $1$ | 単一始点 | $O(V + E)$ | `std::deque` |
| **ダイクストラ法** | **すべて非負 ($c \ge 0$)** | 単一始点 | $O((V + E) \log V)$ | `std::priority_queue` (最小ヒープ) |
| **ベルマン・フォード法** | 負の辺あり（負閉路検出可） | 単一始点 | $O(V \times E)$ | 配列の反復緩和 |
| **ワーシャル・フロイド法** | 負の辺あり（全点対） | 全点対 | $O(V^3)$ | 3重ループ（2次元配列） |

> **⚠️ 注意: DFS（深さ優先探索）は最短経路探索には使えない**  
> DFS は一方向に深く進むため、遠回りな経路で先に到達してしまう可能性があります。最短距離の保証はなく、連結成分の判定や閉路検出、木の探索・トポロジカルソートに用います。

## 2. ダイクストラ法の動作原理と正当性

### 基本方針（貪欲法）
「**すでに最短距離が確定した頂点から、まだ未確定の頂点のうち暫定距離が最小のものを確定させる**」を繰り返すアルゴリズム。

1. 始点 $s$ の距離を $0$、他の全頂点を $\infty$ で初期化する。
2. 最小ヒープ（`std::priority_queue`）に `(0, s)` を追加する。
3. ヒープから最も暫定距離が小さいペア `(d, u)` を取り出す。
4. **もし `d > dist[u]` なら、過去にキューに追加された古いゴミ情報なので無視（スキップ）する。**
5. 頂点 $u$ から伸びる各辺 $(u \to v, \text{cost})$ について緩和を試みる：
   $$dist[v] > dist[u] + cost \implies dist[v] = dist[u] + cost$$
   更新された場合、新たなペア `(dist[v], v)` をヒープに追加する。
6. ヒープが空になるまで繰り返す。

### なぜ負の辺があると壊れるのか？
ダイクストラ法は「**非負の辺しか存在しないため、現在ヒープから取り出された最小距離の頂点が、今後他の頂点を経由してさらに短縮されることはあり得ない**」という不変条件（ループ不変条件）に基づいています。  
負の辺があると後から距離が減少し、確定済みとした前提が崩れるため、誤った最短距離を出力したり無限ループに陥ります。

## 3. C++ 実装の重要エッセンス

### ① `priority_queue` の最小ヒープ宣言
```cpp
using P = pair<ll, int>; // (暫定距離, 頂点番号)
priority_queue<P, vector<P>, greater<P>> pq;
```
- 第1引数: 格納する要素型（`P`）
- 第2引数: 内部で利用する基底コンテナ（デフォルトの `vector<P>` を明示）
- 第3引数: 比較関数オブジェクト（デフォルトは `less<P>` で最大ヒープになるため、`greater<P>` を指定して最小ヒープにする）

> **ペアの順序**: `pair` のデフォルトの比較は第1要素（`first`）から順に比較されます。  
> したがって、`(頂点, 距離)` ではなく **`(距離, 頂点)`** の順で持たせることで、余分なカスタム比較関数を書かずに距離昇順の優先度付きキューが得られます。

### ② 必須の枝刈り（`if (d > dist[u]) continue;`）
```cpp
auto [d, u] = pq.top();
pq.pop();

if (d > dist[u]) continue; // 必須！
```
- ある頂点 $u$ に対し、複数の経路から緩和が発生すると、キューの中に同一頂点 $u$ のエントリが複数積まれます。
- 最初にポップされたものが真の最短距離 $dist[u]$ であり、後から取り出された $d > dist[u]$ のものはすでに緩和処理を完了した「古い不要な候補」です。
- この枝刈りを忘れると、無駄な隣接辺探索が大量に走り、最悪ケースで $O((V + E) \log V)$ を大きく超過し **TLE** の原因になります。

### ③ 到達不能判定
```cpp
constexpr ll INF = 1LL << 60;

for (int i = 0; i < N; i++) {
    if (dist[i] == INF) {
        cout << -1 << '\n';
    } else {
        cout << dist[i] << '\n';
    }
}
```

## 4. グラフ・木の探索テクニック（C++20 ローカル再帰ラムダ式）

グローバル変数にグラフ `G` や訪問配列 `visited` を置かずに、`main` 関数内で安全に DFS を行う場合、**C++14/20 の再帰ラムダ式**が非常に便利です。

```cpp
vector<bool> visited(N, false);

// 第一引数に auto self を受け取ることで自己再帰が可能
auto dfs = [&](auto self, int u) -> void {
    visited[u] = true;
    for (int v : G[u]) {
        if (!visited[v]) {
            self(self, v);
        }
    }
};

// 頂点 0 から探索開始
dfs(dfs, 0);
```
- キャプチャ `[&]` により、ローカルに定義されたグラフや状態配列にオーバーヘッドなく直接アクセスできる。
- コンテストごとの変数名衝突や初期化漏れのバグを防止できる。
